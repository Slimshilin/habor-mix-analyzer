## 2. What broke — the panic chain

**Panic 1** (B130, B132 — `neural_network.rs:109:101`):
```
index out of bounds: the len is 1 but the index is 1
```
On line:
```rust
current_in.matrix[i][0] = current_in.matrix[i][0] *
   (neural_network.denormalizationMatrix[0][i] -
    neural_network.denormalizationMatrix[1][i]) +
   neural_network.denormalizationMatrix[1][i];
```
`denormalizationMatrix[0]` had length 1 (from `vec![0.0; 1]` in
`createNNSystem`), but the loop iterated over `current_in.sizes[0]`
which equaled the input layer size (e.g. 8) — classic mismatch
between input-layer dimension and the scalar denorm vectors that
should track output layer.

**Panic 2** (B134 — `model_system.rs:136:43`):
```
called `Option::unwrap()` on a `None` value
```
Line: `let func_sys = system.func_system.unwrap();` — `selectSystem`
hadn't been called for the NN run, so `func_system` was `None`.

Agent's fix at B135:
```bash
sed -i 's/let func_sys = system.func_system.unwrap();/let func_sys = system.func_system.unwrap_or(crate::systems_builder::complexYDddot);/g' src/interfaces/model_system.rs
```

After the unwrap_or fix, testNNRun started progressing (B142-B152
shows `GENERATION[00000]` through `GENERATION[02300]` with reasonable
fit values like 0.018, 0.087, 0.13). But quickSort was O(N²)
and `oneCalculation` allocates `Vec<Vec<f32>>` per matrix per layer
per timestep per individual per generation — extremely slow.

## 4. Notable bugs introduced

1. `denormalizationMatrix` allocated as `vec![0.0; 1]` while loops
   accessed it by input-layer index — sized to the wrong layer.
2. `func_system` left as `None` because `selectSystem` was only called
   for PID controller path, not NN path.
3. `oneCalculation` heavily allocates inside the inner loop:
   `matrixMultiply(...)` returns a fresh `Matrix { matrix: Vec<Vec<f32>>, ...}`,
   `matrixSubstAdd` does the same, `matrixAllValuesFormula` clones — none
   of these reuse buffers as the C code does (heap reuse). For a 6-layer
   network × 1000 timesteps × 100 individuals × 50000 generations, this
   is several billion allocations.
4. `quickSort` recurses with explicit `Vec::push`-built sub-slices
   instead of in-place partitioning — also slow on the 100-element
   fitness vectors but small constant.
