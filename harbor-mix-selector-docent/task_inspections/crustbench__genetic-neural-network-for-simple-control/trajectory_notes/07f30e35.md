## 4. Notable bugs introduced

1. **stdin defaults left exposed**: `cliSignalSelector`, `selectSystem`,
   etc. still print prompts and read from stdin. Tests don't pipe
   anything, so the read returns immediately with an empty string;
   the agent's `unwrap_or(1)` defaulting works, but the prompts spam
   stdout (visible in B266).
2. **Signal lengths**: `signal_designer.rs` (B270) uses
   `length = 10; dt = 0.01;` (signal length in seconds, then
   `size = (length / dt) as usize = 1000`). But the C reference uses
   `length = 1000` (already in samples) and then loops over
   `0.0 < i < 0.3` and `0.3+dt < i < 10.0` — semantically the same step
   signal but `Signal.length` is stored differently (C: number of
   samples; Rust: seconds). Downstream the agent's
   `makeSimulationOfSignalNN` iterates `0..signal.length as usize`
   meaning `0..10`, NOT 0..1000 — only 10 samples instead of 1000.
   This effectively turns the genetic algorithm into a near-no-op
   per-individual evaluation (testPIDRun is fast at 5000 gen because
   each gen only simulates 10 samples). But this in turn means fit
   values are wrong and the genetic algorithm probably never converges
   — so even though the test compiles/runs, the *physics* is broken.
3. **No findUForSystemAndSignal / findUOneRound** logic — these were
   left as stubs.
