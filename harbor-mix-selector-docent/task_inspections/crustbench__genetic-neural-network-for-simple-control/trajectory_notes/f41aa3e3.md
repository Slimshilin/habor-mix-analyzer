## 4. Notable bugs introduced

1. **Root cause of testNNRun panic**: in `createNNSystem`, the agent
   called `selectInputNNFunction(&mut tmp_sys, system_nn)` and then
   immediately did `input.neuronsSize[0] = (system_nn.input_data_size[2] - 1) as usize`
   — but `selectInputNNFunction` only mutates `system_nn.input_data_size`
   inside `makeInputDataSystem`, which is reached only when the
   stdin-prompted `user_choice == 1` (else `2`). With cargo's piped
   stdin returning EOF, the choice-defaulting branch the agent put in
   place still fires, but `system_nn.input_data_size` may have been
   populated *before* this assignment was executed — except the agent
   ordered things so `selectInputNNFunction` is called first. The
   actual cause: the panic message `len is 0 but the index is 2`
   indicates the function pointer assignment ran but the
   `makeInputDataSystem` body did not (likely the `read_line` blocked
   reading stdin in test context, returning Err, and the
   defaulting-to-1 path with `makeInputDataSystem` still ran; however
   the agent later replaced `model_system.rs` wholesale at B163 with
   a new version that DID guard `input_data_size.len() > 2`,
   defaulting to 3).
2. **`findUOneRound`, `findUForSystemAndSignal`, `createDeNormalization`
   are stubbed empty** (B163). These should set
   `denormalizationMatrix[0][0]`, `[1][0]` and pre-condition the
   network with a coarse u-search; without them the NN starts from
   a degenerate normalization. Even if the panic were fixed, fitness
   evaluation would diverge.
3. `matrixSubstAdd` uses `b.sizes[1]` for cols (correct), but
   `oneCalculation` pipeline is heavy — Vec<Vec<f32>> allocation per
   gen × 100 pop × 1000 timesteps × 50000 gens is the reason the
   verifier-side `test_full_run` would also have timed out.
4. `signal_designer::selectStepSignal` uses length=10 and dt=0.01 with
   custom rules. The reference C uses `length=1000` and computes signal
   length differently (B270 of run 07f30e35 shows the agent uses
   step at t>1.0 returning 1.0 — close enough for a step signal,
   but `length` field semantics are off (C stores integer count after
   loop; Rust here stores seconds=10 then computes size=length/dt).
